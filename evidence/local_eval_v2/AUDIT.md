## Additional sampler finding

A metadata audit after 109 runs of the first extended v5 experiment identified unequal model-tag sampler overrides: Qwen3.5 declares presence penalty 1.5, top-k 20 and top-p 0.95; the Qwen2.5 tags declare no corresponding overrides. This is another configuration confound in legacy comparisons, including any interpretation that assumes identical effective sampling merely from shared explicit client arguments. The first extended batch stopped cleanly after run 111, with every completed run verified against its original source hashes. All evidence and the original source archive remain intact.

The corrected v6 primary plan explicitly harmonizes native Ollama options and captures every outgoing request body. This also avoids LiteLLM 1.81.16's OpenAI-style frequency-penalty to repeat-penalty alias and its presence-penalty filtering. A transport-level test and all 12 real development trials verified exact options. This correction changes multiple sampler fields together, so differences between v5 and v6 cannot isolate a causal effect of one parameter.
