# Literature-to-Design Analysis & Independent Multi-Agent Findings (D-v2 & E-v2)

This document captures Deliverables 1–3 of the CSC2108 Enhanced Contract (`D-v2`) and Diagnosis (`E-v2`) overnight R&D investigation:
1. Literature-to-implementation gap analysis across all five source papers and the project proposal;
2. Independent research findings, forensic audits, and design recommendations from all three participating agents (Gemini 4 Neon, Claude Opus 5.5, Codex GPT-6.2 Sol) before cross-exposure, followed by the cross-agent critique resolutions;
3. Complete record of hypotheses investigated, including explicitly rejected approaches and negative findings.

## 1. Literature-to-Implementation Gap Analysis

> **Archival Note on Paper Filenames**: In `Automated-Reasoning/papers/`, `2310.01831v2.pdf` is **Endres et al. (FSE'24, *nl2postcond*)** and `contract frontier paper.pdf` is **Tufano et al. (SpecOps'26, *Spec-Driven Test Generation*)**.

| Source Paper | Core Mechanism in Literature | Original Project Implementation (`D-v1`, `E-v1`, `frozen-v6`) | Key Omissions / Structural Gaps | Setting-Specific Reality (AtCoder + `qwen3.5:9b`) |
|---|---|---|---|---|
| **Endres et al. (FSE'24)** (`2310.01831v2.pdf`, *nl2postcond*) | LLM translates natural-language specifications into **executable relational postcondition assertions** `(input, output) -> bool`; evaluated offline on **test-set correctness** (0% false rejection on valid references) and **bug-completeness** (mutant kill rate against natural buggy programs). Simple prompts maximize soundness; base prompts maximize bug discrimination (arithmetic equality kills 82% of natural bugs vs 14% for type/shape checks). | `D-v1` generated a single prose specification (`contract-v1`) prepended to the user prompt; **0 executable assertions** were compiled or run in the official 900-run benchmark. Pass 4 `D-active` executed 4 point-test K-checks per task (32/32 valid, 20/27 dev mutants killed, 0/6 TLEs). | (1) **Zero execution** in official `D-v1`; (2) **59/60 official D contracts used 0 reasoning tokens** (36 total vs 11,488 for C plans); (3) prose test suggestions frequently restated public samples; (4) upfront text perturbed turn-1 decoding of a near-deterministic local sampler (`abc393_f` flipped both ways across seeds: +6 wins / -4 losses); (5) no offline Endres mutant benchmark before live runs. | Competitive programming outputs are often a single count/optimum, so type/format checks alone are weak — **but** statement-derived **executable postconditions + metamorphic relations + stress generators** (`D2-Property`) and **bounded exact specification evaluators** (`D2-Oracle`) bridge the execution gap without revealing an efficient solution algorithm. |
| **Tufano et al. (SpecOps'26)** (`contract frontier paper.pdf`, *Spec-Driven Test Generation*) | Two-phase workflow: Phase I derives a structured semi-formal contract from **existing code/tests**; Phase II generates and **executes** tests (`run_test`) against candidate code. Reports **+4.2 pp** bug detection at `k=1` (n.s.) and **+9.8 pp** at `k=5` (`p=0.035`); detection jumps from 19.4% to 54.9% when the contract captures the violated property. | Borrowed the 5-heading contract structure and `Unverified` tags, reversed direction to statement -> implementation, and omitted Phase II execution completely in `D-v1`. | **Phase II test execution missing**; author ≠ consumer; no grounding of `Tested`/`Untested` obligations against actual execution. | Even in Tufano et al.'s native setting, `k=1` pass improvement is modest (+4.2 pp, n.s.). Moving from prose to an executed verification gate is necessary to realize Phase II, while local-agent repair uptake remains a separate bottleneck. |
| **Chong et al. (ICML'26)** (`chong26b.pdf`, *CUDAnalyst*) | Multi-tool feedback (**debugger + static analyzer + profiler**) feeds structured diagnostics to a PlanAgent across iterative refinement loops; evaluates interventions via frozen-trajectory states and ablations. Proves misaligned/unverified feedback degrades every model; concise summaries disproportionately help weaker models; tool synergy matters. | `E-v1` fired once on the first qualifying public failure (`WA`/`RE`/`TLE`/`CE`) with raw source + public judge report only, returning unstructured prose diagnosis. | (1) **Single feedback channel** (public report only — no static complexity analyzer, no stress profiler, no post-diagnosis verification); (2) **81.7% (147/180) of runs never triggered** (byte-identical to A), because 48/180 truncated before writing code and 13/180 passed public tests on attempt 1; (3) "dual" diagnoses (quick bug fix + asymptotic warning) caused `qwen3.5:9b` to apply only the cheap patch and submit (7/7 dual diagnoses failed hidden tests!). | On the 33 triggered `E-v1` runs, **33/33 diagnoses found a genuine defect** (E 14/33 vs A 11/33 = +3 net rescues, 0 losses), proving frontier diagnostic *accuracy* was not the bottleneck — **trigger reach, missing analyzer/profiler evidence, dual-fix temptation, and post-diagnosis verification** were. |
| **Yang et al. (NeurIPS'24)** (`swe paper.pdf`, *SWE-agent*) | Agent-Computer Interface (ACI) design: explicit `THOUGHT` + action channel every turn, informative edit/lint receipts, and bounded observation history. | `frozen-v6` (`heredoc-v6-16k-common`) stripped upstream mini-SWE-agent's `THOUGHT` channel ("Return just the ONE current command block"), discarded length-truncated assistant outputs from history, returned bare `<returncode>0</returncode>` on file writes, and capped context at 16K tokens. | No dedicated deliberation channel -> `qwen3.5:9b` deliberated in Python comments inside an unclosed heredoc (median **93.2% comments** across all 48 A `truncated_no_program` runs), hit the 4,096-token output cap on calls 1, 2, 3, saw a constant 303-char rejection message, and died with `RepeatedFormatError` before ever writing or testing a single file. | This shared local-agent interface bottleneck explains why **48/180 A runs, 44/180 D runs, and 48/180 E runs** terminated with zero programs, whereas Condition C collapsed truncations to **5/180** simply by settling method discovery before call 1. |
| **Wang et al. (ICLR'25)** (`planning frontier paper.pdf`, *PlanSearch*) | Searches natural-language observations and solution sketches before code generation. | Condition C transferred a single upfront `plan-v1` sketch from `gpt-6.2-sol` (+18.3 pp over A, Holm `p=0.0006`). | N/A (reference upper-bound planning condition). | Establishes the crucial **conceptual boundary**: any D-v2 or E-v2 variant that supplies a full solution algorithm/data structure before failure must be explicitly classified as *planning* or *feedback-conditioned planning*, not pure contract or pure failure diagnosis. |

## 2. Independent Multi-Agent Research Findings (Pre-Cross-Exposure)

Before sharing hypotheses across agents, all three available agents conducted independent read-only investigations of the codebase, papers, pass 1–4 history, and the 900-run official `final-main` dataset:

### 2.1 Lead Researcher — Gemini 4 Neon (`gemini-4-neon`, `xhigh`)
- **Core Diagnosis**: Reconciled all pass 1–4 docs (`ar-pass2`) against `final-main`: confirmed paper filename swap, verified 0/180 contract self-checks in `D-v1`, verified 147/180 untriggered E runs, and audited `guided_agent/{backend,diagnosis,providers,runner}.py` to map clean extension seams without touching any of the 38 frozen files.
- **Key Architectural Proposal**:
  - Separate D-v2 into an **isolated, statement-only executable verification bank** compiled in a throwaway Docker container (`D2-Oracle` vs `D2-Property` vs `D2-InputsStress` control) with **zero upfront prompt perturbation** (triggered only after an authoritative public pass) and rotating fresh-seed pools to prevent counterexample overfitting.
  - Separate E-v2 into three causally clean policies: **`E2-Strict`** (same 1st public-failure trigger + deterministic CUDAnalyst AST/timing evidence packet + committed `LOCAL-FIX | METHOD-CHANGE` single strategy + non-blocking advisory V-checks), **`E2-Stall`** (adaptive 2nd-consecutive-truncation trigger conditioned on discarded truncated deliberation, controlled against neutral nudge and `C-late`), and **`E2-Review`** (code-aware silent-unless-verified review gate at 1st public pass, paired directly against `D2-Oracle` to isolate the value of inspecting candidate code).
  - Run an **offline Endres mutant benchmark** first across all exposed `final-main` tasks with >=1 passing reference and >=1 public-pass hidden-fail mutant (18 tasks, 96 passing references, 46 public-pass mutants), then live dev cohorts, then **outcome-blind validation on untouched `test5`**, plus a targeted `<=12` request direct OpenAI API validation under a strict `$10 / 20-request` ledger.

### 2.2 Independent Analysis — Claude Opus 5.5 (`claude-opus-5-5`, `high`)
- *Thread link*: `[Independent Claude Opus 5.5 research & design analysis for D-v2 and E-v2](t3-thread://v2/fd93db2a-39c4-4b05-8019-ac0d95c2fd7e/thread:delegated-task:command%3Amcp%3A8be4a75e-3e53-4d01-aab6-686c251eee6c%3Adelegate-task%3Aa309dd99-7a05-4f2b-a8e4-f91cccaae566)`
- **Independent Empirical Findings**:
  - Verified **59/60** official D contracts used **0 reasoning tokens** (36 total vs 11,488 for C).
  - Verified all **147/147** untriggered E runs were byte-identical to A; on the 33 triggered runs, E passed 14 vs A's 11 (**+3 net rescues**); caught that **7/7 "dual" diagnoses** (local patch + asymptotic caveat, e.g., `abc394_e`) ended in hidden failure because `qwen3.5:9b` applied only the cheap local patch.
  - Corrected Pass 3's outdated "no E exact repeats" claim: found **29 post-diagnosis exact repeats** across 4 `final-main` E runs (`arc191_a` ×3, `abc390_g`).
  - Ran offline counterfactuals (no GPU/API): tiny brute-force differential testing caught 100% of tested public-pass WA programs (`arc194_d` ×5, `arc196_a`, `abc397_b` ×4) with 0 false alarms on B/C references, while max-size timing caught both tested TLEs (`abc400_c`, `abc389_d`).
  - Identified the 28-task / 123-mutant natural mutant pool in `final-main` and warned that `final-main`'s 23 potentially-unseen tasks have too few gate-reachable failures (only 3 non-B-fail PPHF runs) to validate a gate mechanism — recommending `test5.jsonl` for outcome-blind validation.
- **Key Recommendations & Explicit Skeptical Prior**:
  - Recommended **D2-A (gated executable-oracle contract)** as primary D-v2, **D2-B (non-oracle invariant/metamorphic contract)** as scientific control (predicting a low **20–40% prior** bug-completeness on count/optimum problems!), and **E2-1 (strict + analyzer/profiler + committed mode)**, **E2-2 (stall diagnosis controlled against `C-late`)**, and **E2-3 (silent-unless-verified code review gate)**.
  - Emphasized upfront that **D2-A is effectively a statement-authored bounded test oracle**, that **E2-2 is feedback-conditioned planning**, and that **detection does not guarantee local-agent repair** on `qwen3.5:9b`.

### 2.3 Independent Analysis — Codex GPT-6.2 Sol (`gpt-6.2-sol`, `high`)
- *Thread link*: `[Independent Codex GPT-6.2 Sol forensic & engineering analysis for D-v2 and E-v2](t3-thread://v2/fd93db2a-39c4-4b05-8019-ac0d95c2fd7e/thread:delegated-task:command%3Amcp%3A8be4a75e-3e53-4d01-aab6-686c251eee6c%3Adelegate-task%3A01aca25e-fbaf-4d00-b070-b79052f10f05)`
- **Independent Forensic & Engineering Findings**:
  - Completed a full 900-run census + individual audit of all **60 frozen D contracts** and all **33 delivered E diagnoses** (14 passes, 19 failures), verifying all 38 frozen file hashes matched.
  - Quantified the exact truncation trigger precision: **1st-call length stop** fires on **82/180** runs (including **9** eventual A passes), whereas **2nd consecutive initial length stop with no source** fires on **59/180** runs — capturing **48/48 (100%)** of `truncated_no_program` failures and 9 other failures with only **2** eventual A passes (**96.6% failure precision, 97.9% pass specificity**). Also confirmed **median 93.2% comment share** and **0 byte-identical consecutive responses** in no-program truncations.
  - Audited all 6 D wins vs 4 D losses (`abc393_f` appearing on both sides) and exposed hidden churn in D's `public_pass_hidden_fail` count (18 -> 17 masked 10 removed and 9 newly introduced).
  - Mapped exact implementation seams in `guided_agent/{backend,diagnosis,runner,providers}.py` and `minisweagent/agents/default.py:88`, warning that waiting until the 3rd consecutive `FormatError` is too late (terminal `RepeatedFormatError`) and that `guided_agent/providers.py`'s Codex audit is post-hoc unless hardened with a full event-lifecycle check + separate ledger enforcement.
- **Key Recommendations**:
  - Prioritize executable witnesses/metamorphic/stress checks with strict isolation outside the agent container, paired against an inputs-only control; keep strict E-v2 separate from adaptive stall E-v2; require explicit non-blocking advisory checks and `C-late` / neutral controls; use full reruns rather than fragile prefix-replay; enforce strict `$10 / 20-request` ledger with fail-closed behavior if missing.

## 3. Cross-Agent Critique & Resolved Design Decisions

Both Claude Opus 5.5 (`[Claude Opus 5.5 cross-agent critique](t3-thread://v2/fd93db2a-39c4-4b05-8019-ac0d95c2fd7e/thread:delegated-task:command%3Amcp%3A8be4a75e-3e53-4d01-aab6-686c251eee6c%3Adelegate-task%3Aab163eb6-fb62-4f78-8e21-93322e166413)`) and Codex GPT-6.2 Sol (`[Codex GPT-6.2 Sol cross-agent critique](t3-thread://v2/fd93db2a-39c4-4b05-8019-ac0d95c2fd7e/thread:delegated-task:command%3Amcp%3A8be4a75e-3e53-4d01-aab6-686c251eee6c%3Adelegate-task%3Ace1986ad-3899-46f9-a310-9318dd8ebb68)`) critiqued the unified plan before code freeze. Every critique was resolved directly in code:

| Design Tension | Critique Raised | Final Resolution Implemented |
|---|---|---|
| **1. `D2-Oracle` vs `D2-Property` scientific claim** | Codex noted `D2-Property` is the cleanest test of executable postconditions vs prose, while `D2-Oracle` is a *statement-authored differential test* that must be labelled honestly. Claude noted a single frontier call can author both simultaneously for matched comparison and API efficiency. | **Single call (`D2_BUNDLE_V1`)** produces `validate_input`, `gen_small`, `gen_stress`, `check_postconditions`, `metamorphic_pairs`, and `reference_small`. Evaluated all three matched ablations (`D2-inputs-stress`, `D2-property`, `D2-oracle`) offline AND live, plus a pure zero-oracle `D2-property` offline check. Labelled `D2-Oracle` explicitly as a bounded statement-authored differential oracle. |
| **2. Sandbox isolation of `reference_small` & model-authored code** | Both agents warned that running model-authored code inside the agent's container leaks `/tmp` / process state (turning D2 into "reference solution available") and shares writable state/resources. | All untrusted module execution (`compile_d2_bank`, `check_postconditions`) and candidate evaluation (`evaluate_candidate_against_bank`, `E2Review` reproduction) run inside **disposable throwaway Docker containers** (`--network none --read-only --user 65534:65534 --memory 512m --pids-limit 64 --cap-drop ALL --security-opt no-new-privileges`), completely outside the agent container and host Python process, with AST whitelisting. |
| **3. Stall trigger timing (1st vs 2nd length stop)** | Claude initially proposed 1st length stop (82/180 runs, 9 passes); Codex proved 2nd consecutive initial length stop with no source gives **96.6% failure precision / 97.9% pass specificity** (48/48 no-program failures, only 2 passes). | Adopted **2nd consecutive length stop with no candidate source**, hooking `FormatError` in `EnhancedAgent.step()` and re-raising untouched so stock `n_consecutive_format_errors` stays identical (preserving the exact 3-error limit on `frozen-v6`). |
| **4. Blocking vs advisory `E2-Strict` V-checks** | Both warned that blocking submission on an unverified model-authored V-check risks rejecting valid solutions if the V-check itself is buggy. | `E2-Strict` V-checks are **strictly non-blocking advisory**: calibrated against triggering code (dropped if it fails to reject the buggy candidate), never blocks `python -I /public/check.py` returncode `0`, and logs exact verdict alignment. |
| **5. Prefix-replay vs full reruns** | Claude proposed prefix-replay for speed; Codex warned prefix-replay risks diverging sandbox state, `Budget` counters, and dual-clock telemetry. | Used **100% authentic full reruns** via `guided_agent.backend.bound_run` on `frozen-v6`, verifying all 38 frozen file hashes on every attempt. |
| **6. Validation cohort & API budget** | Claude & Codex converged on deterministic, outcome-blind `test5.jsonl` selection (`auto_category == 'exact'`, `needs_review == False`, zero prior use) and strict separation of free isolated Codex replay vs `<=12` direct OpenAI API requests under a `$10 / 20-request` fail-closed ledger. | Selected `test5_val16.json` (8 medium + 8 hard, pinned `test5.jsonl` sha256 `7f77571c...`), enforced fail-closed ledger in `enhanced_de/ledger_guard.py`, and segregated all `codex-replay` vs `openai-api` tables. |

## 4. Hypotheses Investigated (Including Rejected Approaches)

| Hypothesis / Approach | Status | Outcome / Rationale |
|---|---|---|
| **H-D0 (Rejected upfront)**: Upfront "reformulation contract" giving mathematical equivalences | **Rejected pre-implementation** | Collapses into Condition C (planning/method insight), violating the conceptual boundary between contracts ("what") and plans ("how"). |
| **H-D1 (Rejected upfront)**: Showing D2 prose contract upfront before turn 1 | **Rejected pre-implementation** | Official `D-v1` and Pass 4 proved upfront text perturbs turn-1 decoding of near-deterministic `qwen3.5:9b`, creating symmetric noise (`abc393_f` +1/-1) and confounding execution vs prompt perturbation. |
| **H-D2**: Statement-only executable postconditions + metamorphic relations + stress (`D2-Property`) vs bounded differential oracle (`D2-Oracle`) vs inputs/stress control (`D2-InputsStress`), gated silently on public pass | **Implemented & Tested (Phase 0 + Phase 1A + Phase 2)** | Phase 0 offline benchmark (18 tasks, 96 refs, 46 public-pass mutants): **0/96 (0.0%) FRR** for all 3 modes; kill rates **34.8%** (`inputs-stress`), **82.6%** (`property` — decisively refuting the 20–40% skeptical prior!), and **87.0%** (`oracle`, 18/18 tasks detected). Live uptake tested in Phase 1A & Phase 2. |
| **H-D3 (Deferred)**: Local agent writes its own brute-force oracle from prose contract (Tufano cognitive scaffold) | **Deferred (low priority)** | Consumes scarce `qwen3.5:9b` actions/tokens and risks common-mode misreading; deprioritized in favor of testing clean harness-isolated `D2-Property` vs `D2-Oracle`. |
| **H-E1**: Strict first-public-failure diagnosis enhanced with CUDAnalyst deterministic static/timing analyzer packet, committed single-mode `LOCAL-FIX | METHOD-CHANGE`, and non-blocking advisory V-checks (`E2-Strict`) | **Implemented & Tested (Phase 1B + Phase 2 + Phase 3)** | Directly targets the 8 post-diagnosis `public_pass_hidden_fail` runs (including 7/7 dual-advice failures) while preserving exact `E-v1` trigger semantics. |
| **H-E2**: Adaptive stall diagnosis at 2nd consecutive no-source length stop conditioned on discarded truncated deliberation (`E2-Stall`), controlled against `E2-Stall-Neutral` (placebo) and `C-late` (frozen `plan-v1` delivered at same stop) | **Implemented & Tested (Phase 1C + Phase 2 + Phase 3)** | Targets the dominant 48/180 `truncated_no_program` bottleneck with 96.6% historical failure precision; `C-late` cleanly separates trace-conditioned diagnosis from late-delivered planning. |
| **H-E3**: Code-aware silent-unless-verified review gate at 1st public pass (`E2-Review`) | **Implemented & Tested (Phase 1A + Phase 2 + Phase 3)** | Paired directly against `D2-Oracle` at identical public-pass states to isolate the causal value of inspecting candidate code vs statement-only specification. |
| **H-E4 (Rejected)**: Triggering stall diagnosis on 1st length stop or blocking submission on unverified V-checks | **Rejected pre-implementation** | 1st length stop fires on 9 eventual A passes (noisy perturbation); blocking on unverified V-checks risks false rejections of correct programs. |
